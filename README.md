# 맞혀볼래? (가칭) — AI 맞히기 게임 1차 버전

업무 원장 "AI game App" 블록의 첫 결과물이에요. 기획 분석(`D:\Taeho\reports\2026-10-30\game\report.md`)의 결론대로
**공통 퀴즈 뼈대를 먼저 만들고, 그 위에 1순위 게임 "명대사 듣고 작품 맞히기"를 올렸어요.**
2순위 "노래 → AI 그림 → 제목 맞히기"는 화면과 데이터 구조만 만들고 샘플 그림으로 흐름을 확인했어요.

- **아직 배포하지 않았어요.** 인터넷 주소도 없어요. 이 컴퓨터에서만 열려요.
- **DB 를 쓰지 않아요.** 문제는 저장소 안의 JSON 파일, 점수 기록은 각자 기기(localStorage)에만 남아요.
- **돈 드는 API 를 부르지 않아요.** 음성은 휴대폰·PC 에 원래 들어 있는 음성 읽기 기능(무료)을 써요. API 키도 필요 없어요.

## 1. 지금 만든 것

### 공통 퀴즈 뼈대 (앞으로 만들 게임이 모두 함께 씀)

| 화면 | 하는 일 |
|---|---|
| 홈 | 퀴즈 묶음 목록 (인기순·최신순), 내 최고 점수 |
| 묶음 시작 | 진행 방법, 점수 규칙, 소리 확인(명대사), 내 최고 기록 |
| 문제 | 그림 또는 재생 버튼 · 정답 입력(Enter 로 제출) · 힌트 · 건너뛰기 · 기회 2번 |
| 정답 공개 | 정답/오답, 공식 제목, 연도·장르, **출처 표시**, 내가 낸 답 |
| 결과 | 점수, 맞힌 개수, 걸린 시간, 공유 문구 복사, **공유 카드 이미지**(저장·공유), 다시 하기 |

- **채점**: 띄어쓰기·문장부호·대소문자를 무시해요. 줄임말·영어 제목도 정답으로 인정해요.
  예) "범죄와의 전쟁" = "범죄와의전쟁" = "범죄와의 전쟁: 나쁜놈들 전성시대" = "Nameless Gangster" = "범죄와의 전쟁 (2012)"
  한두 글자 틀리면 "아까워요!"라고만 알려 주고 정답 처리는 하지 않아요("범죄도시2"와 "범죄도시3"이 같아지면 안 되니까요).
- **힌트**: 초성(ㅂㅈㅇㅇ ㅈㅈ) → 연도 → 장르 순서. 게임마다 추가 힌트 하나(명대사는 "대사 보기", 노래는 "그림 설명 보기").
- **점수**: 바로 맞히면 100점, 두 번째 기회에 맞히면 70점, 힌트 하나에 −20점, 추가 힌트 −10점, 맞히면 최소 20점.
- **공유 칸**: 🟩 힌트 없이 한 번에 · 🟨 힌트나 두 번째 기회로 · 🟥 틀림 · ⬜ 건너뜀 (카톡에 붙여 넣기 좋게)
- 휴대폰 화면 기준으로 만들었고, 키보드만으로도 끝까지 할 수 있어요(입력칸 이름표, 초점 이동, Enter 제출, 화면낭독기 안내).

### 게임 ① 명대사 듣고 작품 맞히기 (`quote_tts`) — 지금 바로 할 수 있어요

- 영화 21문제 · 드라마 16문제. 문제마다 **짧은 대사 한 줄**을 기기의 **일반 한국어 TTS 음성**이 읽어요(여성 음성이 있으면 먼저 골라요).
- 다시 듣기, 속도(느리게·보통·빠르게) 조절. 대사 글자는 정답을 확인한 뒤에만(또는 "대사 보기" 힌트로) 보여요.
- 기기에 한국어 음성이 없으면 안내 문구를 띄우고 대사를 글자로 보여 줘요(감점 없음).

### 게임 ② 노래 → AI 그림 → 제목 맞히기 (`song_image`) — 자리만 만들어 둠

- 데이터 구조와 그림 문제 화면이 동작해요. 샘플 5문제는 **코드로 그린 단순한 그림**이고 화면에 "샘플 그림 · AI 생성 아님"이라고 표시돼요.
- 실제 앨범 표지·뮤직비디오 장면·가사는 쓰지 않았어요.

### 지키는 원칙 (기획 보고서의 법적 위험 정리를 그대로 반영)

- 음성은 **일반 TTS 음성만**. 배우 목소리 복제·흉내·"OO처럼" 연출 없음. 음높이·속도로 특정인을 흉내 내지 않아요.
- **배우 이름을 문제·화면·홍보 문구 어디에도 쓰지 않아요.**
- 대사는 **한 문제에 한 줄**(60자 이하, 자동 검사). 정답 공개 때 **작품명·연도를 출처로 표시**해요.
- 영화 스틸컷·포스터·원본 음성은 쓰지 않아요. 화면은 글자와 직접 만든 그래픽뿐이에요.
- 화면 아래에 "대사는 출처 표시 목적의 짧은 인용이에요" 안내와 **"AI·TTS 음성"** 표시를 붙였어요.
- 노래 그림은 가사를 쓰지 않고, 실제 출시 그림에는 **"AI 생성"** 표시를 붙이도록 데이터에 칸을 만들어 두었어요.

## 4. 노래 그림 게임을 진짜로 만들려면

1. **그림 API 결정** (대표 결정): 보고서 기준 gpt-image-1-mini 약 15원/장, Gemini 2.5 Flash Image 약 55원/장. 후보 4장이면 문제당 60~220원, 100문제에 약 6천~2.2만원. [가격은 계약 전 공식 페이지에서 재확인]
2. **API 키는 서버(Cloudflare Workers)에만** 두고, 화면 쪽에는 절대 넣지 않아요.
3. **프롬프트에는 우리가 쓴 분위기 설명만** 넣어요(`sceneDescription`). 가사·가수 이름·앨범 표지 묘사는 넣지 않아요.
4. **사람이 후보 4장 중 1장을 골라요** — "맞힐 수 있지만 너무 쉽지 않은" 그림. 이 고르기 화면(관리자 검수 화면)이 필요해요.
5. 고른 그림은 **Cloudflare R2 에 한 번만 저장**하고 계속 재사용 → 플레이할 때마다 돈이 들지 않아요.
6. 데이터는 `image: { kind: "file", src, alt, aiModel }` 로 넣으면 화면에 자동으로 **"AI 생성 · 모델 이름"** 표시가 붙어요.
7. 정답 공개에 공식 뮤직비디오 링크(`officialLink`)를 붙여요. 음원은 우리 서버에 두지 않아요.
8. 첫 30~50문제로 정답률을 재고 난이도를 맞춘 뒤 늘려요.

### 하루 흐름 (사람이 하는 일은 3번 한 가지)

| 단계 | 명령 | 하는 일 | 사람? |
|---|---|---|---|
| 1 | `npm run daily:generate -- --provider openai` | 곡 대기열의 **맨 앞 곡** 하나를 골라, 우리가 쓴 분위기 설명으로 그림 **4장**을 만들어 `candidates/날짜/` 에 저장 | 자동 |

| 4 | `npm run daily:publish -- --date 2026-11-12` | 고른 그림을 **Cloudflare R2 에 올리고**, 노래 그림 묶음(`src/data/song-image-daily.json`)에 문제를 추가, 대기열에서 그 곡을 "완료"로 | 자동 |
| 5 | `npm test` → 검수(`needsReview` → `false`) → 배포 | 제목·연도·그림 확인 후 배포는 대표님 승인 | 사람 |

- 곡 대기열: `scripts/daily-song-image/data-queue/songs.json` — **30곡**(제목·가수·연도·별칭·장르 + 우리가 쓴 분위기 설명), 상태는 `pending`(대기)/`done`(완료). 곡을 더 넣으려면 같은 모양으로 추가하면 되고, 가사 칸(`lyrics`/`가사`)이 있거나 설명에 금지어·제목·가수 이름이 들어 있으면 검사에서 막혀요. **연도·제목·가수는 추가 전에 사람이 한 번 확인해 주세요.**
- `--dry-run` 을 붙이면 프롬프트만 출력하고 **아무것도 쓰지 않고 API 도 부르지 않아요**(generate·publish 둘 다). 키가 없으면 `--dry-run` 없이도 호출 전에 멈춰요.
- `daily:pick -- --date 날짜 --auto-pick-first`: 사람이 보지 않고 1번을 자동 선택해요. **품질이 낮아요**(이상한 그림·글자 섞인 그림이 그대로 나갈 수 있음) — 임시·테스트용이고, 이렇게 올린 문제에는 `autoPicked: true` 가 남아요.
- 그림 서비스는 바꿔 끼울 수 있게 만들었어요(`providers/openai.mjs` = gpt-image-1-mini, `providers/gemini.mjs` = Gemini 2.5 Flash Image). 같은 모양으로 파일 하나 더 만들면 다른 서비스도 쓸 수 있어요.
- R2 업로드는 외부 부품 없이 S3 호환 방식(`lib/r2.mjs`)으로 직접 서명해서 올려요. 올리기에 실패하면 묶음·대기열은 건드리지 않아요.
- 후보 그림 폴더(`candidates/`)는 용량이 커서 git 에 올리지 않아요.
- 묶음 파일 `src/data/song-image-daily.json` 은 **첫 그림이 올라간 뒤에 생기고**, 자동으로 홈에 "오늘의 노래 그림" 묶음으로 보여요(샘플 표시 없음, 화면에 "AI 생성 · 모델 이름" 표시).

### 비용 (보고서 기준 · 계약 전 공식 가격 재확인)

| 서비스 | 1장 | 하루 4장(후보) | 한 달(30일) |
|---|---|---|---|
| gpt-image-1-mini (기본) | 약 15원 | 약 60원 | 약 1,800원 |
| Gemini 2.5 Flash Image | 약 55원 | 약 220원 | 약 6,600원 |

R2 저장은 그림 1장이 수백 KB 라 사실상 무료 구간이에요(R2 는 내려받는 요금이 없어요). 후보로 만든 나머지 3장은 올리지 않아요. 한 곡이 마음에 안 들어 다시 만들면(`--force`) 그만큼 더 들어요.

### 대표님이 주셔야 켤 수 있는 것

1. **그림 API 키 하나** — OpenAI(`OPENAI_API_KEY`) 또는 Google AI Studio(`GEMINI_API_KEY`). 결제수단 등록 필요. 이 도구를 돌리는 PC 의 환경변수로만 두고 git 에 넣지 않아요(`.env` 는 이미 git 제외).
2. **Cloudflare R2** — 버킷 1개, API 토큰(읽기/쓰기, 그 버킷만), 공개 주소(커스텀 도메인 또는 r2.dev). 환경변수: `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET`, `R2_PUBLIC_BASE_URL`
3. **매일 3번(고르기)을 할 사람** — 하루 1분 남짓. 원칙은 사람이 고르기.
4. 곡 목록의 **연도·제목 확인**과 **변호사 확인**(아래 원칙이 AI 기본법 표시 기준에 충분한지)

### 법적 안전장치 (코드로 막아 두었어요)

- **가사 금지**: 대기열에 가사 칸 자체를 둘 수 없고, 그림 프롬프트는 곡 정보 중 **분위기 설명 한 줄만** 읽어요(테스트로 확인). 제목·가수 이름·연도도 프롬프트에 안 들어가요.
- **얼굴·닮은꼴 금지**: 프롬프트에 "실존 인물·얼굴·연예인 닮은꼴 없음"을 항상 붙여요. 그림 소재도 풍경·사물 위주로 썼어요.
- **앨범 표지·뮤직비디오 모방 금지**: 프롬프트에 "기존 앨범 표지·포스터·뮤직비디오·저작물 모방 금지"를 항상 붙이고, 설명에 "앨범/표지/뮤직비디오" 같은 말이 있으면 거절해요. 사람이 고를 때도 닮은 그림은 버려요.
- **글자 없는 그림**: "글자·숫자·간판·로고·워터마크 없음"을 항상 붙여요(그래도 섞이면 사람이 고르며 걸러요).
- **"AI 생성" 표시**: 묶음 데이터에 `aiModel` 이 반드시 들어가고, 화면에 "AI 생성 · 모델 이름"이 붙어요. 모든 문제는 `needsReview: true` 로 시작해요.

### 매일 자동으로 돌리려면 (설명만 — 설정하지 않았어요)

- **Windows 작업 스케줄러**: 매일 오전 9시에 `npm run daily:generate -- --provider openai` 를 실행하는 작업을 만들고, 대표님·담당자가 출근해서 2~3번을 해요. 단점: 그 PC 가 켜져 있어야 해요.
- **Cloudflare Cron Trigger(Workers)**: 같은 일을 서버가 매일 해 줘요(그림 4장 생성 → R2 임시 폴더 저장 → 검수 화면은 관리자 페이지로). 장점은 PC 가 필요 없다는 것, 단점은 지금 만든 "내 PC 검수 화면"을 관리자 화면으로 옮기는 개발이 더 필요하다는 점이에요(6장 "관리자 화면"과 함께 하면 좋아요). 이 경우 API 키는 Workers 의 시크릿으로만 보관해요.
- 어느 쪽이든 **고르기와 배포 승인은 사람이** 하는 구성을 권해요.
